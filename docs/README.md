# PhotoCompressorService

Репозиторій: https://github.com/Pro100NeFarT/PhotoCompressorService

Локальна служба для стиснення та конвертації фото, яку викликає 1С перед записом
картинки в базу. Приймає зображення по HTTP, зменшує розмір/розширення за заданими
параметрами, WEBP завжди конвертує в JPEG.

## Архітектура

- Python (Flask + Waitress), запакований в один exe (PyInstaller) — Python на цільовій
  машині не потрібен.
- Встановлюється як Windows-служба (через NSSM), автозапуск разом з системою.
- 1С звертається до служби звичайним HTTP-запитом (`HTTPСоединение`/`HTTPЗапрос`) —
  працює однаково для тонкого, товстого й веб-клієнта, бо сервер 1С сам виконує запит.
- За замовчуванням слухає тільки `127.0.0.1` — служба має стояти на тій самій машині,
  що й сервер 1С. Якщо потрібно інше — див. розділ "Конфігурація".

## Встановлення

1. Запустити `PhotoCompressorService-Setup-<версія>.exe` від імені адміністратора.
2. Інсталятор ставить службу в `Program Files\PhotoCompressorService`, реєструє її
   через NSSM з автозапуском і одразу стартує.
3. У меню Пуск з'являється група ярликів: головна сторінка, папка логів, файл
   конфігурації, документація. За бажанням інсталятор також пропонує створити
   ярлик головної сторінки на робочому столі й одразу відкрити її по завершенні.
4. Перевірка: відкрити в браузері `http://127.0.0.1:8788/` — має відкритись головна
   сторінка сервісу з прикладом роботи алгоритму (або `http://127.0.0.1:8788/health`
   для простої перевірки `{"status": "ok", ...}`).

Перевстановлення (оновлення версії) коректно зупиняє й перереєстровує службу;
`config.json` і логи в `%ProgramData%` не чіпаються.

Видалення — через "Програми і компоненти" Windows або ярлик "Видалити" в Пуск.
Служба зупиняється й видаляється; конфіг/логи в `%ProgramData%\PhotoCompressorService`
залишаються (можна видалити вручну).

## Конфігурація

Файл `%ProgramData%\PhotoCompressorService\config.json` (створюється автоматично
при першому запуску з дефолтними значеннями). Зміни застосовуються після
перезапуску служби (`services.msc` → Photo Compressor Service → Перезапустити).

```json
{
  "host": "127.0.0.1",
  "port": 8788,
  "max_upload_mb": 25,
  "log_level": "INFO",
  "compression": {
    "max_width": 1920,
    "max_height": 1920,
    "max_size_kb": 300,
    "quality_start": 90,
    "quality_min": 40,
    "quality_step": 5
  },
  "update": {
    "enabled": true,
    "github_repo": "Pro100NeFarT/PhotoCompressorService",
    "check_interval_hours": 24
  }
}
```

| Поле | Призначення |
|---|---|
| `host` | Адреса, на якій слухає служба. `127.0.0.1` — тільки з цієї ж машини. |
| `port` | TCP-порт. |
| `max_upload_mb` | Захист від надто великих запитів. |
| `log_level` | `DEBUG` / `INFO` / `WARNING` / `ERROR`. |
| `compression.*` | Дефолтні параметри стиснення — застосовуються, якщо 1С не передала свої в запиті. |
| `update.enabled` | Вмикає перевірку оновлень на головній сторінці. |
| `update.github_repo` | Репозиторій у форматі `власник/репозиторій`, з якого читаються GitHub Releases. |
| `update.check_interval_hours` | Як часто повторно опитувати GitHub (результат кешується). |

**Параметри стиснення, як правило, зручніше передавати з кожного запиту з 1С**
(див. API нижче) — тоді для різних довідників/реквізитів можна задавати різні ліміти
без зміни конфігурації служби.

## API

### `GET /health`
Перевірка живості. Відповідь:
```json
{"status": "ok", "service": "PhotoCompressorService", "version": "1.0.0"}
```

### `POST /compress`
Запит (усі поля, крім `image_base64`, опційні — дефолти беруться з `config.json`):
```json
{
  "image_base64": "<base64 вхідного файлу>",
  "max_width": 1920,
  "max_height": 1920,
  "max_size_kb": 300,
  "quality_start": 90,
  "quality_min": 40,
  "quality_step": 5
}
```

Відповідь при успіху:
```json
{
  "success": true,
  "changed": true,
  "image_base64": "<base64 результату, завжди JPEG якщо changed=true>",
  "format": "JPEG",
  "width": 1920,
  "height": 1280,
  "size_kb": 245.3,
  "quality_used": 82,
  "original_format": "JPEG",
  "original_width": 3000,
  "original_height": 2000,
  "original_size_kb": 4210.5
}
```

Якщо `changed=false` — зображення вже вкладалось у ліміти й повернуте без змін
(нуль втрат якості); `quality_used=null`.

Логіка вибору формату:
- WEBP на вході — завжди конвертується в JPEG.
- JPEG/PNG, що вже вкладаються в ліміти розміру й ваги — повертаються без змін.
- Усе, що перевищує ліміти — масштабується (без апскейлу) і зберігається як JPEG
  з поступовим зниженням якості (крок `quality_step`) до `quality_min`, якщо
  інакше не вкластися в `max_size_kb`.

Відповідь при помилці (HTTP 400/500):
```json
{"success": false, "error": "текст помилки"}
```

### `GET /` (алиас `/test`)
Головна сторінка сервісу: приклад роботи алгоритму, ручна перевірка на власному фото
(ті самі параметри, що приймає `/compress`), кнопка генерації готового BSL-коду для 1С
під поточні виставлені параметри, і банер про доступне оновлення (якщо є).

### `GET /update-check`
Перевіряє GitHub Releases репозиторію з `config.json` (результат кешується на
`check_interval_hours`). Додати `?force=1`, щоб проігнорувати кеш. Відповідь:
```json
{
  "enabled": true,
  "current_version": "1.0.0",
  "latest_version": "v1.1.0",
  "update_available": true,
  "download_url": "/update-download",
  "asset_name": "PhotoCompressorService-Setup-1.1.0.exe",
  "asset_size_mb": 14.6,
  "release_notes_url": "https://github.com/.../releases/tag/v1.1.0"
}
```
Якщо `update.enabled=false` — повертає лише `{"enabled": false}`.

### `GET /update-download`
Перенаправляє (HTTP 302) прямо на файл інсталятора останнього релізу на GitHub.
Використовується кнопкою "Завантажити оновлення" на головній сторінці — браузер
завантажує інсталятор як звичайний файл, після чого користувач сам відкриває
завантажене (стандартна поведінка браузера), і встановлення проходить так само,
як описано в розділі "Встановлення" вище (з підтвердженням UAC).

## Приклад виклику з 1С (BSL)

```bsl
// Возвращаемое значение — Структура:
//  * ДвоичныеДанные - результат сжатия (JPEG) при Успех = Истина,
//                      либо исходные данные без изменений при Успех = Ложь
//  * Успех          - Булево - Истина, если сервис вернул JPEG (нужно поменять расширение файла)
//
// ВАЖНО при интеграции со стандартной подсистемой "Файлы": подмены переменной
// ДвоичныеДанные часто НЕДОСТАТОЧНО, если сохранение файла ниже по коду берёт
// содержимое из АдресФайлаВоВременномХранилище, а не из этой переменной. См. пример ниже.
Функция СжатьФото(ДвоичныеДанные, МаксШирина = 1920, МаксВысота = 1920, МаксРазмерКБ = 300) Экспорт

	СтруктураОтвета = Новый Структура;
	СтруктураОтвета.Вставить("ДвоичныеДанные", ДвоичныеДанные);
	СтруктураОтвета.Вставить("Успех", Ложь);

	Попытка
		Соединение = Новый HTTPСоединение("127.0.0.1", 8788, , , , 10);

		Тело = Новый Структура;
		Тело.Вставить("image_base64", Base64Строка(ДвоичныеДанные));
		Тело.Вставить("max_width", МаксШирина);
		Тело.Вставить("max_height", МаксВысота);
		Тело.Вставить("max_size_kb", МаксРазмерКБ);

		ЗаписьJSON = Новый ЗаписьJSON;
		ЗаписьJSON.УстановитьСтроку();
		ЗаписатьJSON(ЗаписьJSON, Тело);
		СтрокаТела = ЗаписьJSON.Закрыть();

		Заголовки = Новый Соответствие;
		Заголовки.Вставить("Content-Type", "application/json");

		Запрос = Новый HTTPЗапрос("/compress", Заголовки);
		Запрос.УстановитьТелоИзСтроки(СтрокаТела);

		Ответ = Соединение.ОтправитьДляОбработки(Запрос);

		Если Ответ.КодСостояния <> 200 Тогда
			Возврат СтруктураОтвета; // сервис вернул ошибку — оставляем оригинал
		КонецЕсли;

		ЧтениеJSON = Новый ЧтениеJSON;
		ЧтениеJSON.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку());
		Результат = ПрочитатьJSON(ЧтениеJSON, Ложь);
		ЧтениеJSON.Закрыть();

		Если Результат.Свойство("success") И Результат.success Тогда
			СтруктураОтвета.Вставить("ДвоичныеДанные", Base64Значение(Результат.image_base64));
			СтруктураОтвета.Вставить("Успех", Истина);
		КонецЕсли;

		Возврат СтруктураОтвета;

	Исключение
		// служба недоступна/не запущена — не блокируем работу пользователя
		Возврат СтруктураОтвета;
	КонецПопытки;

КонецФункции
```

Виклик, наприклад у розширенні стандартної процедури `РаботаСФайлами.ДобавитьФайл`
(зверни увагу на оновлення адреси тимчасового сховища — це критично, інакше фізично
збережеться оригінал, попри "успішне" стиснення):

```bsl
СтруктураОтвета = СжатьФото(ДвоичныеДанные);
Если СтруктураОтвета.Успех Тогда
	ДвоичныеДанные = СтруктураОтвета.ДвоичныеДанные;
	АдресФайлаВоВременномХранилище = ПоместитьВоВременноеХранилище(ДвоичныеДанные, АдресФайлаВоВременномХранилище);
	Если РасширениеБезТочки = "webp" Тогда
		РасширениеБезТочки = "jpg";
	КонецЕсли;
КонецЕсли;
```

> Код наведено як орієнтовний приклад (мовою BSL, стандартний "російськомовний"
> синтаксис 1С) — деталі `HTTPСоединение`/`HTTPЗапрос` можуть відрізнятись залежно
> від версії платформи. Перед впровадженням перевірте у тестовій обробці.

## Логи та діагностика

- `%ProgramData%\PhotoCompressorService\logs\service.log` — власний лог застосунку
  (запуск, помилки стиснення), ротація по 5 МБ, 5 файлів.
- `%ProgramData%\PhotoCompressorService\logs\stdout.log` / `stderr.log` — вивід
  процесу, який перехоплює NSSM (корисно, якщо служба не стартує взагалі).
- Служба не стартує:
  - `services.msc` → Photo Compressor Service → перевірити стан і "Останню помилку".
  - Перевірити, чи порт `8788` (чи інший з конфігу) не зайнятий іншим процесом.
  - Подивитись `stderr.log` — найчастіша причина: некоректний `config.json`
    (тоді служба працює на дефолтних значеннях і пише попередження в лог).
- 1С не може достукатись: перевірити `http://127.0.0.1:8788/health` браузером
  безпосередньо на сервері 1С.

## Оновлення версії

Запустити новий інсталятор — він сам зупинить і перереєструє службу. Конфігурація
не втрачається.

## Публікація нового релізу на GitHub (для автооновлення)

Щоб банер "Доступне оновлення" на головній сторінці спрацював у вже встановлених
користувачів:

1. Підняти версію в `app/config.py` (`VERSION`) і в `installer/setup.iss`
   (`AppVersion`) — обидва місця мають співпадати.
2. Зібрати exe і інсталятор (`PyInstaller` → `ISCC setup.iss`).
3. Створити на GitHub реліз з тегом `vX.Y.Z` (наприклад `v1.1.0`) і прикріпити до
   нього зібраний `PhotoCompressorService-Setup-X.Y.Z.exe` як asset.
4. Служби з увімкненим `update.enabled` самі побачать новий тег протягом
   `check_interval_hours` (або одразу — кнопка перевіряє миттєво при відкритті
   головної сторінки, з кешем на цей інтервал).

Порівняння версій — за числовим тегом (`v1.2.3` → `(1,2,3)`), тому теги мають бути
у форматі семверу.
